# 座舱多语提示的错因归类与版本放行

内容席处理多语提示错因和版本适用证据。主提示与可替代信息以资料所给服务条件为准。

## 资料和运行环境

`data/` 提供本地合成业务资料。各业务文件为 UTF-8 JSON 数组，键、单位和关联见 [资料字典](data/README.md)。`format.json` 记录列集合和基础引用约束。

使用 Python 3.11。在普通 Python 环境可用 `python3 -m pip install -r requirements.txt` 安装锁定的分析依赖。检查提供的资料可运行：

```sh
python3 -m unittest discover -s tests -v
```

资料检查覆盖文件可读性、字段与明确的单列引用。业务原始记录允许保留冲突、未决关系及尚未到达的观察。

## 漏标审查管线

`cabin_review/` 是可复用到以后版本的漏标审查管线：用实际播出清单、内容席初分错因、旅客线索、抽取机会和双人复核，估计关键错因(语义反转、播放不清、线路不适用)漏标率并支撑版本放行判断。

```sh
# 做一次审查：生成 out/report.md 与 out/state.json
python3 -m cabin_review run --data data --out out

# 只看某日之前可见的裁定(还原当时的金标准)
python3 -m cabin_review run --data data --out out --as-of 2026-08-01

# 新裁定到达后比较两轮状态：哪些要重算、在用版本哪些要收窄、
# 已启动的补抽是否还能回答原问题
python3 -m cabin_review diff out/state.json 新状态.json
```

口径要点：

- 内容席初分(`first_labels`)是抽核前的漏标基准，盲审裁定只更新金标准，不回写基准。
- 总体漏标率与版本比较只用盲抽样本(按登记概率逆概率加权，旅程聚类标准误)；线索追查片段单列，不进总体率。
- 同一真实译文在多处使用不等于多次独立审查；语义反转、播放不清可在同场景内随译文传递，线路不适用随应用条件变化、不传递；跨线路的通过不算独立抽样。
- 初审分歧无裁定、已抽未审的错因不按无漏标计，展开为区间上下限；层内登记概率为 0 记为无观察机会。
- 补抽建议按“哪些证据可能解除发布限制”排序；班位编排校验双语与关键指引资格，已发出待确认的复核仍占班位。
